# Pixiv 发图与音乐界面更新

基于 ichinose-custom 提交 2879c104c6142880db0453e62ce28e66aa5b8755。

- 聊天输入 `/pixiv 作品ID` 或 `/pixiv https://www.pixiv.net/artworks/作品ID`，发送公开作品。多图先下载完整组，再按页发送普通图片消息；支持收藏表情、历史记录和群聊 / 私聊。输入 `/pix` 可补全。
- 图片由本服务下载并存入现有 ImageMessage 上传目录，不依赖第三方图片代理。服务器需要能访问 www.pixiv.net 和 i.pximg.net。没有加入 Pixiv 账号登录；受限作品、下载失败会由 system 回复原因。
- 单张上限 20 MB，整组上限 100 MB / 200 张。超过上限会明确失败，不截断成部分图片；下载失败会清理临时写入的图片。
- 顶部播放器、命令提示采用半透明毛玻璃。当前没有歌曲时隐藏播放器；有空闲歌曲播放时仍显示，暂停时也保留控制。点歌入口始终保留在音乐面板。
- 在“音乐 → 导入歌单 → 空闲播放模式”选择顺序或随机。默认为顺序，群主 / 站点管理员及私聊参与者可修改，按房间持久化。切换从下一首生效，不打断当前歌曲。随机模式避免紧接着重复当前曲目，原歌单顺序不变，手动点歌始终优先。

## 应用

补丁包包含增量补丁和按仓库路径排列的 files/ 文件。请在上述版本的仓库根目录运行：

```sh
git apply --check /path/to/fiora-custom-update.patch
git apply /path/to/fiora-custom-update.patch
docker compose up -d --build
```

也可将 files/ 内的内容按相同路径覆盖。服务端和前端应一起更新。保留现有 .env、上传目录和数据卷，不需要重新配置音乐适配器。

前端生产构建成功（资源体积提示仍存在）。针对性检查覆盖 Pixiv ID / 链接校验、多图发送、失败清理、空闲顺序 / 随机和手动点歌优先；用一个公开作品完成实际下载。未进行服务器部署或 GitHub 推送，未运行大范围回归测试。
